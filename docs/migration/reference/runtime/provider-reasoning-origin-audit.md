## Decision

Use `adapt`. Preserve Eino-ext Agentic OpenAI's rule that provider-specific
reasoning is accepted only from a self-generated message, but replace its
message-local boolean with project-owned proof of the exact provider account,
API family, API model, route, and credential origin that generated the private
material.

The boolean is necessary adapter state, not sufficient trust evidence. It is
set on a response object and can be lost during stream aggregation or forged
when a caller or transcript supplies `Message.Extra`. Eino-Agent now rejects
persisted assistant message-level `Extra` at the classic-to-Agentic bridge, so
today's production behavior remains conservative. P38 may create the adapter
marker only as an attempt-local consequence of exact route proof.

## Reproduced current path

The current pipeline preserves the private block until the downstream request
conversion:

| Stage | Verified behavior | Security consequence |
|---|---|---|
| Agentic response | `agenticToMessage` and the stream accumulator copy reasoning text and `Reasoning.Signature` into classic assistant output parts | The canonical round can retain the encrypted continuation material |
| Stream aggregation | Canonical aggregation joins public and private output parts but does not preserve the Agentic message's self-generated classification as trusted route evidence | A restored stream response has data but no authorization to reuse it |
| Transcript and Session replay | P36.1 proves the complete classic message reaches durable transcript, Session clone, and the next model-call history | Recovery is lossless enough to expose the missing origin boundary |
| Route selection | `routingChatModel.prepareRoute` resolves the actual model immediately before Generate or Stream | This is the last owner that knows the selected client and API model before conversion |
| Classic-to-Agentic bridge | `messagesToAgentic` reconstructs reasoning blocks but rejects all persisted assistant message-level `Extra` | A forged `openai-generated` value cannot authorize private reuse |
| Eino-ext request conversion | A non-self-generated assistant message skips block types outside a model-agnostic allowlist; reasoning is not allowlisted | Public text and function-tool history continue, while the reasoning item is omitted before HTTP transport |
| Alternate failover | `stripSignatureBlocks` removes legacy reasoning, every structured reasoning/signature part, and message-level `Extra` from the attempt-local clone | Cross-route fallback is conservative and leaves canonical history unchanged |
| ACP load/replay | The P36 projector validates public assistant text and excludes private reasoning, signatures, and provider metadata | Provider continuation must not be smuggled into a public entrypoint projection |

This is G34: a same-route restored conversation loses useful private
continuation even though the durable bytes survived. Sending those bytes on
provider-name equality alone would trade a correctness gap for a credential
and cross-account disclosure flaw.

## Why current identities are insufficient

`RouteIdentity` is a non-secret provider-client cache key. It contains provider,
endpoint, auth kind/reference, and adapter digest. Its comments deliberately
exclude profile IDs, API model names, and resolved secrets. Two model profiles
can therefore reuse one client even when their exact API model differs.

`PersistedModelBinding` records provider, API model, portfolio revision, route
digest, metadata digest, limits, and reasoning effort. It deliberately contains
no account, endpoint, credential, header, client, or route-health data. It can
reselect a user-visible model after restart, but cannot prove that one private
reasoning item was generated by the credential now used for dispatch.

Neither record is wrong for its owner. The P38 trust decision has a stronger
identity requirement and must not broaden either cache or presentation
contract merely to reuse it.

| Candidate proof | Missing fact | Decision |
|---|---|---|
| Provider name | Account, API family, model, credential, route publication | Reject |
| Profile ID | A presentation selector can change or point to another account/model | Reject |
| `RouteIdentity` digest | Exact API model and credential rotation identity | Reuse as one field, never as the full proof |
| `PersistedModelBinding` | Exact account and credential origin | Reuse for recovery consistency only |
| Adapter `openai-generated` boolean | Durable route provenance and caller authenticity | Generate only after exact proof; never persist as authority |
| Reasoning/signature payload shape | Any origin fact | Reject |

## Comparative evidence

| Source | Verified behavior | Adoption consequence |
|---|---|---|
| Eino-ext Agentic OpenAI | `message_extra.go` sets and tests exact boolean `openai-generated`; `convertor.go` skips reasoning for non-self-generated assistant input and maps `Reasoning.Signature` to Responses `encrypted_content` | Preserve the adapter's fail-closed conversion and generate its marker only from a project-owned trusted decision |
| Claude Code Ripe | `stripSignatureBlocks` removes thinking, redacted-thinking, and connector signature blocks because signatures are bound to the API key and become invalid after credential change such as `/login` | Credential rotation must invalidate reuse, not merely change a display profile |
| OpenCode | `message-v2.ts` forwards provider metadata only when persisted provider/model equals the target provider/model | Preserve the exact provider/model minimum, but strengthen it with account, route, API-family, and credential identity |
| Codex | Responses requests include `reasoning.encrypted_content`; history keeps encrypted reasoning as a distinct response item and checks encrypted-content identity while merging | Keep private continuation structurally distinct from public text; do not infer a portable account-origin scheme that the inspected path does not provide |
| Eino-Agent | Route selection owns the actual client; transcript/Session own durable messages; ACP owns a public-only replay projection | Combine these owners through one private sidecar and an attempt-local route check, without adding a second transcript or public projection |

No reference supplies the complete Eino-Agent contract. OpenCode's
provider/model comparison is useful but does not distinguish two accounts of
the same provider. Claude Code Ripe proves that credential identity matters.
Eino-ext supplies the leaf conversion guard. The project must join those facts
at its existing route and transcript owners.

## Frozen origin implications

The durable origin needs exactly these non-secret fields:

- schema version;
- canonical provider;
- configured account ID, not a profile label;
- API family/protocol, such as Agentic OpenAI Responses;
- exact API model sent to the provider;
- existing canonical route-identity digest; and
- an opaque, rotation-sensitive credential-origin ID supplied by the
  credential resolver.

The credential-origin ID is neither the raw credential nor an unkeyed hash of
it. It must be stable for the same locally resolved credential, change on
rotation, and become unavailable rather than guessed after a machine move or
credential-store reset. A resolver that cannot provide such an ID makes
private continuation ineligible.

Durable equality is still not sufficient during a concurrent publication or
reload. `routeRegistry` must own immutable published client snapshots and
re-resolve credential origin before every cache reuse. First construction,
credential-origin change, account/route/API-family change, invalidation/reload,
or client reconstruction publishes a new object and monotonic revision under
the registry serialization boundary.

The router captures that immutable object with the actual client, then
rechecks it immediately before classic-to-Agentic conversion. Recheck plus
one-attempt client-bound proof issuance is the linearization point. A changed
or missing revision before that point strips private state. Publication after
that point cannot mutate the captured client or transfer the proof to a new
attempt. A later attempt resolves the new route again.

The sidecar must also bind more than logical `message_id`, because that value
is message metadata. The accepted association combines persisted physical
`MessageEntryIdentity` and message index, the internal logical assistant ID,
and a canonical digest of the persisted assistant payload. Fork, rewrite,
compaction, and recovery may transfer the origin only through an atomic exact
rebind; every mismatch strips.

## Lifecycle and failure matrix

| Event | Required result |
|---|---|
| Same account, API family, API model, route digest, and credential origin | Eligible only after the current route publication is rechecked |
| Manual model switch | Strip before transport with `origin_api_model_mismatch` |
| Provider or API-family switch | Strip with the matching provider/family reason |
| Bounded failover to another account or route | Strip before the alternate call; never mutate canonical history |
| Credential rotation or `/login` equivalent | Strip with `origin_credential_mismatch` |
| Missing pre-P38 origin | Treat as absent or legacy-unverified and strip |
| Invalid/unsupported origin schema | Preserve transcript readability, expose no private values, and strip |
| Session recovery with physical entry/index, logical ID, or payload mismatch | Strip with `origin_recovery_mismatch` |
| Route publication changes after capture | Strip with `origin_route_stale` |
| ACP load/replay/export | Omit the origin sidecar and all private provider material |

Diagnostics are bounded reason codes. They never contain account references,
endpoints, route digests, credential IDs, signatures, encrypted content, model
input, or credential material.

## Recommendation

Promote P38.0 as one `Ready` implementation slice under `adapt`. It may add the
private origin sidecar, route-owned capture/recheck, attempt-local marker, and
redacted diagnostics only after the characterization fixture remains green.
Rollback is today's conservative behavior: strip all private continuation and
preserve public text/tool history. No broader provider-metadata replay, public
ACP field, cross-provider translation, or heuristic reuse belongs in P38.0.
